## `orderparam_check_`：可确定的局部计算合同

反编译给出四个指针/地址参数。结合汇编访存可给出以下**机器级合同**：

- 参数 1：指向 32 位整数 `n`，控制有效向量分量数。
- 参数 2：指向 32 位整数 `m`，控制需要检查的向量列数。
- 参数 3：实 double 矩阵 `D` 的起始地址；矩阵列之间相隔 `0x180 = 48×8` 字节。
- 参数 4：实 double 向量列集合 `E` 的起始地址；相邻列同样相隔 48 个 double。

在正常、有限且维度满足上游存储合同的输入上，以 1 起始数学下标描述，例程计算：

\[
r_{ij}=\sum_{k=1}^{n} D_{ik}E_{kj}-E_{ij},
\qquad i=1,\ldots,n,\quad j=1,\ldots,m .
\]

其中内存中 `D[i,k]` 的零起始位置是 `i + 48k`，`E[i,j]` 的位置是 `i + 48j`。
这是固定 leading dimension 48 的列优先存储。实际有效维度 `n` 不必等于 48；
也不能因为有 48 的步长便宣称接口会安全接受任意大于 48 的维度。

每个残差交给 `ncmp_`，任一返回非零便立即返回 0；所有残差判零后返回 1。
关键汇编位置：

- `0x4b4861..0x4b486a`：double 乘法和求和。
- `0x4b486e`：矩阵下一列加 `0x180` 字节。
- `0x4b4813`：减去对应输入向量分量。
- `0x4b4828..0x4b482f`：调用 `ncmp_` 并根据结果失败返回。
- `0x4b489d..0x4b48a3`：转到下一向量列。

**语义判断：** 若 `D` 是某群元素在选定实表示中的矩阵，则该例程检查每一个输入
向量是否被逐点固定，即 `D(g)E=E`。这强于只要求 `span(E)` 作为子空间保持不变。
它不是求特征向量、不是模式投影、不是求空间群编号，也没有在本例程内归一化 `E`。

**边界：** `m≤0` 会直接返回 1；`n≤0` 时每列检查为空，也会返回 1。汇编和伪代码
都没有在此例程中进行完整的维度/有效性检查。这不是上游程序接受非法维度的证据，
也不能把这里的返回 1 当作输入有效性认证。未对非有限数值做动态试验；不能声称
这条判断自动排除了 NaN、Infinity 或所有无效内存输入。

## `ncmp_`：固定绝对阈值，而非物理位置容差

REA 原样伪代码为：

```c
bool ncmp_(double *param_1)
{
  return 1e-06 < ABS(*param_1);
}
```

因此，在有限残差的适用条件下，观察到的规则是：

\[
\operatorname{ncmp}(r)=
\begin{cases}
0,& |r|\leq\tau,\\
1,& |r|>\tau,
\end{cases}
\qquad \tau \text{ 的反编译十进制表示为 }10^{-6}.
\]

比较是严格 `>`：等于所存阈值时判零。这里没有相对误差项，没有按 `‖E‖` 或
矩阵范数自动缩放，也没有从用户输入中读取这个阈值。精确 IEEE-754 常数字节及其
边界运行行为未在本审计另外抽取/动态验证，因此不把打印的十进制文本扩充成更多
未经验证的位级结论。

阈值作用于**表示坐标中的残差**。本例程不知道原子位置、Å、晶格常数或
Bohr magneton，因此不能把 `10^-6` 写成“原子位置容差 10^-6 Å”，也不能据此
覆盖 FINDSYM 手册中的独立位置/晶格/磁矩容差。

固定绝对阈值一般对序参量幅度敏感：输入 `E→cE` 后残差同样乘 `c`。
上游是否固定了序参量尺度、是否保证条件数和误差范围，仍需追踪实际生成者。
**从这里读到一个数字，不构成在新算法中直接照搬该容差的理论依据。**

## `orderparam_to_subgroup_`：可观察的组织步骤与参数边界

这段函数不是简单地查“母相号→子群号”的对应表。它使用通用数据库索引、晶格运算、
表示矩阵以及上述逐分量固定条件组织筛选。已经能确定的步骤如下：

1. 参数 1 的整数值用于索引 `common_little_`。从偏移 `0x2d6f6e + 2×index`
   取一个有符号 16 位值，再调用 `generate_space_group_`；另从
   `0x369af7 + index` 取一个有符号字节作为后续表示维度。
   这个参数是与表示表关联的**内部索引**；没有证据把它直接等同于用户输入的
   International Tables 空间群编号。
2. 参数 3 提供每列相隔 48 个 double 的序参量向量；参数 4 给出列数。
   先复制当前列的有效分量。
3. 第一列经 `newlat_order_`，之后调用 `ndet_` 与 `get_new_fractionals_`，
   为候选平移记录分配空间。
4. 后续列调用 `newlat_order3_`、`matinv_`、`matmlt_`、`reduc3_`、
   `get_new_fractionals_`、`vmlt_`、`reduc2_`，再更新当前晶格。
   `reduc3_` 后状态不为 1 时发出 `bomb2_("orderparam_to_subgroup 58",...)`。
   本次没有审读这些被调例程全文，故不把这组函数名直接当作“已经证明的晶格交算法”。
5. 对当前的每个操作记录遍历候选分数平移，用 `vadd_` 组合记录，调用
   `get_irreps_` 取得供检查的实矩阵；其错误状态非零会调用
   `bomb2_("orderparam_to_subgroup 81",...)`。
6. 调用 `orderparam_check_`。其向量数参数取 VA `0x5af834` 的常数 **1**，
   所以这里每次检查当前一列，并非一次把全部列传入；多列在外层逐次处理。
   第一个通过的候选被保留后转向下一个既有操作，未通过才继续尝试下一分数平移。
7. 每条保留记录复制 5 个 32 位值，更新记录数，继续下一序参量列。
   最后参数 6 写出记录数，参数 7 写出操作记录，参数 5 写出 9 个 32 位值的
   晶格表示。

参数 2 被原样传给晶格和表示例程，其精确结构/含义尚未恢复。不能仅因目标任务包含
k 向量，就把它写成已经确认的 `double k[3]`。类似地，输出 9 个整数的矩阵应在哪种
母晶格基下解释，5 整数操作记录中的旋转/分数平移字段如何编码，本次没有逐字段证明。

伪代码中 `local_668[47]` 等局部数组声明与相邻栈槽是反编译器的类型划分；汇编表明
这里存在固定步长缓冲区。不能据这些临时类型直接生成新的 Fortran/C ABI 绑定。
二进制中嵌入的 `../source/orderparam_to_subgroup.f` 和行号是诊断字符串，
**不是已经取得该源文件**。

## 与数学稳定子定义的关系及剩余证明缺口

以下是本项目的数学解释，和“官方文档陈述”分开：

若 `D:G→GL(V)` 是同一坐标约定下的真实群表示，`E` 中每一列都是 `V` 的向量，
精确固定集合

\[
H_E=\{g\in G\mid D(g)E=E\}
\]

构成子群：单位元固定 `E`；若 `g,h` 固定 `E`，则
`D(gh)E=D(g)D(h)E=E`；由 `D(g)E=E` 左乘 `D(g^{-1})` 得逆元同样固定 `E`。
上述乘加例程对应这个定义的局部检查，但有限容差筛选不自动继承精确证明。

一个不依赖网站结果的反例说明为何还需要上游适用条件：取平面旋转群 `C6`，
`g` 为 60° 旋转，`η=(4τ/5,0)`。则

\[
(D(g)-I)\eta=(-2\tau/5,\;2\sqrt3\,\tau/5)
\]

的两个分量绝对值都小于 `τ`；但是

\[
(D(g^2)-I)\eta=(-6\tau/5,\;2\sqrt3\,\tau/5)
\]

第一分量超出阈值。独立对每个操作采用同样的绝对判据会接受 `g` 而拒绝 `g²`，
因此这个近似集合未必闭合。这是关于局部判据的精确代数反例，
**不是已在官方程序正常输入路径复现的缺陷**；上游尺度约定或约束可能排除该例。
本次没有测试该反例是否能通过官方命令入口到达此函数。

对于现有 `runtime/iso-gm4minus-p1/input.txt` 中用户主动指定的
221 / GM4− / P1 / Wyckoff a，真实 stdout 显示 P4mm、指数 6、胞体积比 1。
该输入先固定再运行，没有读官网答案。它支持这条命令实例可用；但没有动态追踪证明
这次具体执行必经上述三个函数，亦不替代对任意 k、复表示、磁性/反幺正或超空间的证明。

后续完整独立实现至少仍需核验：

- `common_little_` 字段来源、版本与索引含义，以及所有有效维度的边界。
- `get_irreps_` 的相位、实化、基序和 k 坐标约定。
- `newlat_order_` / `newlat_order3_` 的整数/有理晶格合同与完备性。
- 操作记录、晶格基变换和最终空间群识别/标准设定的完整链。
- 上游序参量尺度与浮点误差界，容差下的闭包、边界和非有限值策略。
- 畸变模式投影、振幅与官网归一化。这三个函数本身没有给出这些结论。
