# REA 第二阶段：晶格、Wyckoff 与投影内核证据

本报告分析 `evidence/phase2/rea-kernels/04` 至 `12` 的九条 REA
`procedure_pseudo_code` 原始记录，不重新打开或修改二进制。它补充
[模式理论合同](reference_library/MODE_CONTRACT.md)，不替代数学证明或实际运行检查。
所有“观察”指反编译记录可直接看到的内容；对匿名参数、编码和算法用途的解释
另标“推断”。没有读取官网计算案例，也没有把官网模式作为计算输入。

## 证据身份与可复查产物

目标是本项目 `vendor/isobyu/iso` 的 ELF x86_64 副本：

    SHA-256 242b2c6ef93b00007d580eef27a4540018d94467e52e9a0cb81c4c835b37ddc8

提供者为 Ghidra 12.1.3，REA 记录 `confidence=observed`、
`authority=shipped-artifact`。九次工具调用均无 `isError`，这仅说明反编译请求
完成，不意味着反编译文本能编译、数学正确或每个分支均已执行。原始调用记录、
时间和工具错误状态由该目录 `index.json` 保存。

`extract_pseudocode.py` 把各 record 的 `normalized_result` 按原始 UTF-8 文本
导出为同名 `.pseudocode.txt`；`pseudocode_manifest.json` 保存原 JSON 和提取
文本的 SHA-256、字节数、evidence ID、目标 hash、provider 和限制。它没有修改、
翻译或“修复”反编译代码。九个函数共 5,088 行可读文本；主显示函数占 3,267 行，
因此本报告只对明确列出的控制流与计算片段作结论，不宣称读懂所有分支。

REA 提供者明确说明：这是 Ghidra 伪代码，不是原 Fortran 源码；临时数据库在
关闭时删除；该 bridge 核验版本为 12.1.4，本次实际使用 12.1.3。部分函数出现
类型传播未收敛、未知类型和栈变量复用。不能把明显的反编译类型异常移植为算法。

## 1. 空间群操作：紧凑记录展开，不是本函数独立证明群闭包

证据：`04-generate-space-group.json`，
`ev_e3bbbdbcd52462eed43ddd03ac749989660e6ac9be479cce54af0ef245f3a85f`。
对应伪代码第 11–27 行。

**观察：** `generate_space_group_` 从按输入索引寻址的计数/偏移数组取得记录数，
以 `common_space_` 为基址，循环把每条 5 个 byte 型值扩为 5 个 int，并写入
调用方缓冲区。该函数内没有从生成元反复相乘直到闭包的循环。

**推断：** 这是通用空间群操作紧凑表示的展开入口；5 元记录很可能组合旋转编码
与有理平移。仅这段代码不能确定每个分量的完整字典、符号宽度、分母约定或
primitive/conventional setting。不能把“读出一张操作表”等同于已验证它是群。

**对应合同：** MODE_CONTRACT D4–D7 要求下游检验操作闭包、度量保持和置换同态。
表格可作为正式通用数据来源，但不能以该函数名称跳过这些检查。

## 2. Wyckoff 轨道：局部点群与陪集生成

证据：`05-get-wyckoff-all.json`，
`ev_e206c9a0756fc264b0e17bb37bfdf98259ddb536d843e832a82fb37bc9355b26`。
伪代码第 17–58 行。

**观察：** `get_wyckoff_all_` 从 `common_wyckoff_` 读取小整数形式的系数，
对某些零末分量置 1；随后调用 `wyc_pg_elements_` 和 `wyc_pg_cosets_`。
对于多个陪集，反复调用 `vrot_` 变换 4 个向量片段，再调用 `vadd_` 加平移。
返回的数量来自陪集计数。

**推断：** 这与“以站点稳定子陪集展开整个母相 Wyckoff 轨道”的数学构造一致，
并保留可变位置的参数化，而不只是存一个固定实例坐标。数组片段的确切形状/
有理编码仍需独立类型与调用方审计；不能仅按 4×4 外观命名所有变量。

**对应合同：** D3 的轨道展开必须区分母相站点稳定子与完整群，不能把空间群
全部操作作用后所得重复位置直接当作不同原子，也不能仅用一个 Wyckoff 代表
替代全部轨道。

## 3. 子群下轨道分裂与变换：包含晶格商、原点和线性关系

证据：`06-get-new-wyckoff.json`，
`ev_2f0a254a09929d46aa3ca701e95ebcd892c0318959073c17e37311b5c7eb2a90`。
重点伪代码第 111–149、287–423、612–685 行。

**观察：** `get_new_wyckoff_` 构造带额外分量的变换并调用 `matinv4_`；
调用 `get_wyckoff_all_`、`ndet_` 和 `get_new_fractionals_`；将展开位置与新
fractional 向量相加，施加 `vmlt_`、`vadd_`，再通过 `reduc1_`/`reduc2_`
约化。接着用子群操作旋转、加平移、比较和标记等价项。后段出现整数行操作
`rowop2_` 与有理分母/符号处理。容量不足时明确报告 `maxnewcount too small`
并进入 `bomb2_`；不能把该失败当作零个新站点。

**推断：** 这些控制流支持“从母相轨道与平移陪集产生子胞位置，再按子群分轨道，
并整理自由坐标线性关系”的解释。它不仅是把坐标乘一个矩阵。
尚未证明输出每个匿名参数对应哪项站点映射或自由变量，也未证明任意分数基变换
的全部边界行为。

**对应合同：** D2–D4 的原子数、晶格指数、原点变换和可逆映射都不可省略。
这里的整数/有理处理提示不能以没有完备性保证的浮点空间搜索盒替代晶格商。

## 4. 平移晶格由序参量不变性筛选

证据：

- `07-newlat-order.json`：
  `ev_059c79cd6c074dd081951e650e9cc69c7bc374eb1450090064f2d96f3aa20253`。
- `08-newlat-order3.json`：
  `ev_cfe7145dadf08eb6158092a7a78e1162a26f937e69f5a885534a24bef1d51b63`。

**观察：** 两个函数都从 `common_little_` 取得表示相关数据，设置单位点操作，
按整数候选向量循环调用 `get_irreps_`，再调用 `orderparam_check_` 判断候选。
找到三个向量后，通过彼此加减的操作降低最大绝对坐标分量。
`newlat_order3_` 还先做 `matinv_`，对候选调用 `vmlt_`、`reduc2_`，要求
约化后的某个分母量为 1 后才进行表示/序参量检查。两者有明确的错误分支。

**推断：** 这与“求固定 OPD 的平移子格，并整理基向量”的功能吻合；第三版
还受一个输入晶格约束。看到 `get_irreps_ + orderparam_check_` 是比仅凭
函数名更强的证据：平移晶格依赖表示和 OPD，不能一般地取单个 k 分母的对角超胞。
但当前记录没有恢复其完整参数规范，也没有证明该基整理过程等同于 HNF/SNF、
Minkowski reduction 或全局最短基算法，报告不作这种命名。

**对应合同：** D1–D3 要使用完整 k/OPD 平移稳定条件；晶格大小和 subgroup
index 仍需与群/原子计数独立交叉检验。伪代码中异常的局部数组索引可能来自
Fortran 栈布局识别，不能直接判断为原程序越界缺陷。

## 5. 表示不是全部预存的最终矩阵：稀疏系数与相位组合

证据：`09-get-irrep4-ssgn.json`，
`ev_73e7c753967d8a7082521477790ca55cb51747b26a12116a46af85a043aa0fd2`。
伪代码第 30–48、85–115 行。

**观察：** `get_irrep4_ssgn_` 按空间群建立操作映射，清零目标矩阵；
从 `common_little_` 的偏移表读取三元稀疏记录，用 `constant_` 将常数编码转换
为值并写到矩阵。随后调用 `get_irreps_ssg_phase_` 和 `xmatmlt_`，将相位相关
矩阵与已装入的矩阵相乘。

**推断：** 该专用路径至少具有“通用表格系数 + 运行时相位 + 矩阵组装”的结构。
这反驳把所有程序能力视作逐材料答案查表的简单解释，但不证明每个 IR/每个 k
都通过这个特定函数，也不能从 `ssgn` 名称断言它就是所有普通三维分支的入口。
记录未完整恢复相位正负号、实/复表示约定或常数编码字典。

**对应合同：** D14 必须区别复不可约与 physical-real 表示，并验证实际
`D(g1g2)=D(g1)D(g2)`。从该段不能直接得到 mode `normfactor` 或实际结构幅度。

## 6. 局部 IR 投影：先计数、再筛独立列，含 real/complex 类型分支

证据：`10-project-local.json`，
`ev_67058670283cecf507a3a3b01ff43dfdef1a7f23aa97a7be85d5ee9803e0ebb6`。
重点伪代码第 81–182、214–255、256–399 行。

**观察：**

- 从 Wyckoff、IR 与 image 数据取得维数和一个类型码。
- 在一组对应操作上两次调用 `get_irreps_`，对返回量作乘积求和并除以操作数；
  当类型码为 3 时另乘 0.5，再四舍五入成独立模式数。
- 若计数不近于整数，输出 `non-integer number of independent modes` 并报错。
- 随后对返回矩阵的元素乘积作累加，生成候选系数；按最大绝对分量缩放，
  借助 `zrowop_`/`ncmpz_` 检验独立性；不同类型存在不同维数和实/复处理分支。

**推断：** 结构与局部表示 subduction/交织投影及独立基选择吻合。类型 3 的
0.5 因子与 physical-real/complex 重数问题相关是合理解释，但还需确认具体
枚举码与 `get_irreps_` 的模式参数，不能直接当作已恢复的公式。

**不能据此声称：** 最大分量缩放是某个中间基的表示规范，不是已经完成 Å 单位、
primitive-supercell 统计的 ISODISTORT 位移归一化，更不证明 strain normfactor。
这里没有看到完整晶胞度量/原子重数的最终幅度公式。
末段出现极小 double 常数兼作循环索引等反编译类型异常，应保留而不解释为
物理小量或修补成猜测源码。

**对应合同：** 本地 H 不变投影 D6 是另一种可证明的完整参数化；此段显示
官方软件还进行局部/母群表示处理，因此仅达到同一 H 固定空间不能宣称复现
官方 IR/站点模式列。D14 中的实化警告有了具体二进制类型分支证据。

## 7. 局部表示系数转换成 polar/pseudo vector

证据：`11-project-vector-local.json`，
`ev_9cacbb4a5a80c2a69e0e4e9d0f225611665a851a474f63300663013ad3700c38`。
伪代码第 30–98 行。

**观察：** `project_vector_local_` 从小整数常数表读系数，通过 `constant_`
构造三分量向量，再用 `common_space_` 中的 3×3 数据作用于它。在一个类型
与操作条件成立时引入 −1 的整体因子，返回累计向量数。

**推断：** 该分支与 polar/axial vector 在不正操作下的符号区别一致；需把参数
类型码与正式文档核对后才可把每个匿名变量命名为“磁性”“旋转”等。
不能因为函数中有 3 分量和旋转，就把所有输出都当普通原子位移。

**对应合同：** phase 2 首版普通位移使用 polar Q；磁矩/转动轴向量必须额外
考虑 det(Q)，不能无声明复用普通位移合同。

## 8. DISPLAY DISTORTION 汇集了检查、畴、Wyckoff 与投影

证据：`12-isotropy-display-distortion.json`，
`ev_ad389aeab2cdee02d566ed554c7f594ad5c7530f1e8b3f2b4489fcb64de7e876`。
本次读取了检索命中的相关片段，不宣称 3,267 行的所有分支均已复核。

直接可见的路径包括：

- 第 1007–1015 行检查 Cartesian 输出所需 conventional basis；
  第 1105–1138 行选择 IR 范围并拒绝缺失 k 参数、不一致参数及落到特殊点的参数。
- 第 1271–1284 行在相关 Cartesian/Wyckoff 路径缺少 x,y,z 时明确报错。
  所以无法把任意 Wyckoff 标签配默认零参数作为合法结构输入。
- 第 1651 行附近存在 `generate_domains2_`；第 2981 行附近有
  `generate_domains_`，且随后用 `get_irreps_` 把方向变到所选畴。
  默认畴不能默认为所有次级 IR 的共同嵌入。
- 第 2093 行调用 `project_`，第 2552 行调用 `project_vector_`，
  并经 `vector_change_setting_` / `get_wyc_cartesian_` 等路径作坐标转换。
  这些被调用函数并未在本次九条中全部取得源码级语义。
- 第 2888–2900 行附近的宏观路径按 IR 标签进行条件筛选并调用 `tensor_basis_`；
  使用 rank、tensor symmetry 和 pseudo 标志。结合手册可把它解释为宏观张量
  投影入口，但仅见一个静态字符串比较尚不足以单独恢复全部 Γ 筛选语义。

**对应合同：** 当前普通 H 基实现应独立拒绝缺参数和 setting 不一致，明确
输出其选择的坐标规范；不会自动继承这些官方前置检查。
这份汇总伪代码也不能证明 ISODISTORT PHP 服务器的真实 argv、进程数、部署路径
或导出格式生成调用。它是 `iso` 命令行程序内部证据，不是服务器进程追踪。

## 已建立的机制链与尚未建立的结论

可复查的机制链是：通用群/站点/表示记录 → 操作和轨道展开 → 表示作用与
序参量条件 → 平移子格/畴 → 局部 IR 投影与独立性选择 → 向量/张量及坐标输出。
它与理论合同的对象相符，并显示这些二进制具备可复用的群论计算路径。

尚不能宣称：

- 每个 COMMON 数组字段、Fortran shape、整数编码和文件记录已全部恢复；
- 九个函数已覆盖所有 230 空间群、k 参数、非共形基、磁性或 superspace 情况；
- `DISPLAY DISTORTION` 直接输出当前网站完整、正交且归一化的 mode CIF；
- 本地 H 基保留了全部官方 IR/局部站点标签或现行应变振幅；
- 静态反编译和工具无错误构成科学正确性证明。

对生产实现最直接的要求是：保留精确输入和子群嵌入，以独立的 H 自由度计数、
坐标往返和未应变度量验证完整性；若后续实现 IR 分辨，先通过官方
`SHOW FREQUENCY DIR` 获取通用相容方向，再核对每个 domain 和所有模式块的
总秩。任何查到的类型警告、缺失矩阵、容量不足或 k 诊断都不能被忽略为成功。
